# 授权码与双后台一体化 Spec

## Why
当前系统缺少“付费后安装与使用”的完整授权闭环，无法有效防止授权码被恶意传播。需要将管理后台与用户后台整合到同一系统，并以授权码为核心建立安装、调用、查询全链路校验。

## What Changes
- 在同一套后端中新增 `root` 管理后台能力与普通用户后台能力，基于角色做功能隔离。
- 新增授权码体系：生成、分配、可见、复制、状态流转（未使用/已使用/禁用）。
- 新增管理员用户管理模块：注册用户、分配账号类型（个人/家庭）、发放授权码、删除授权码。
- 新增管理员账单管理模块：查看用户账单明细，按“用户+授权码”分类查看与删除账单。
- 新增快捷指令安装校验接口：仅未使用授权码可安装，安装成功后标记授权码已使用。
- 新增快捷指令记账与用户后台查询的授权校验：请求必须携带永久授权码，并校验“授权码-用户账号”关系。
- 用户后台展示授权码：个人仅1个，家庭最多5个。
- 账号密码初始化规则：管理员创建用户时，初始密码为手机号后6位。
- 新增“V1兼容开关与路由隔离”：V1接口与页面保持原有能力不变，授权码校验仅作用于新方案（V2授权通道）。
- **BREAKING**：无（本次要求保持 V1 功能不变，不做替换式迁移）。

## Impact
- Affected specs: 用户认证、角色权限、授权码管理、快捷指令安装校验、账单管理、后台可视化
- Affected code: `backend/app/models/*`、`backend/app/schemas.py`、`backend/app/api/auth.py`、`backend/app/api/transactions.py`、`backend/app/api/families.py`、`backend/main.py`、`frontend/index.html`

## ADDED Requirements
### Requirement: 角色化统一后台
系统 SHALL 在同一登录体系下支持 root 管理员与普通用户两类角色，并展示不同功能模块。

#### Scenario: root 登录后台
- **WHEN** root 账号登录成功
- **THEN** 可访问用户管理、授权码管理、账单管理模块

#### Scenario: 普通用户登录后台
- **WHEN** 普通用户登录成功
- **THEN** 仅可访问自己的账单与授权码信息，无法访问管理模块

### Requirement: 授权码发放与绑定
系统 SHALL 支持管理员按账号类型发放永久授权码，并维护授权码与用户的关系。

#### Scenario: 个人账号发码
- **WHEN** 管理员创建个人账号
- **THEN** 系统仅生成1个永久授权码并可复制

#### Scenario: 家庭账号发码
- **WHEN** 管理员创建家庭账号
- **THEN** 系统生成5个永久授权码并可复制

### Requirement: 快捷指令安装校验
系统 SHALL 仅允许“未使用授权码”通过安装校验，成功后立即改为“已使用”。

#### Scenario: 安装成功
- **WHEN** 用户输入有效且未使用的授权码
- **THEN** 返回安装许可并将该授权码状态更新为已使用

#### Scenario: 安装失败
- **WHEN** 用户输入无效/已使用/禁用授权码
- **THEN** 返回安装拒绝，不允许安装继续

### Requirement: 调用与查询授权
系统 SHALL 在快捷指令记账调用和用户后台账单查询时校验“授权码+用户账号”关系。

#### Scenario: 记账调用成功
- **WHEN** 请求携带有效授权码且与账号匹配
- **THEN** 账单写入该用户数据域

#### Scenario: 查询调用成功
- **WHEN** 用户后台查询携带有效授权码且匹配账号
- **THEN** 返回该注册账号下的全部账单数据

### Requirement: V1功能不变
系统 SHALL 保持 V1 现有功能、页面与接口行为不变，不影响已在用用户。

#### Scenario: V1 用户正常使用
- **WHEN** V1 用户按原路径访问与使用系统
- **THEN** 功能、数据读写与交互表现与修改前一致

#### Scenario: 新方案与V1并行
- **WHEN** 管理员启用授权码新方案
- **THEN** 仅新方案通道启用授权码校验，不影响V1原有通道

## MODIFIED Requirements
### Requirement: 用户创建流程
管理员创建用户时，系统将手机号作为账号标识，初始密码自动设置为手机号后6位，并强制首次登录后可修改密码。

### Requirement: 账单管理可见域
账单明细在管理后台支持按“用户账号、授权码”进行分类检索，普通用户仅查看本人数据；V1账单视图保持原有逻辑。

## REMOVED Requirements
### Requirement: 无授权码直接使用快捷指令核心能力
**Reason**: 无法满足先付费后使用与防传播要求。  
**Migration**: 仅“新快捷指令安装与调用通道”迁移为授权码校验；V1通道不迁移、不下线。
