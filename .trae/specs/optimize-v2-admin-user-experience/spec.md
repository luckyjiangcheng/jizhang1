# V2管理端与用户端体验优化 Spec

## Why
当前 V2 已具备授权与后台能力，但在登录方式、管理端操作效率、家庭管理规则和整体视觉层级上仍不满足你的产品运营目标。需要在仅保留 V2 的前提下统一交互与权限策略，降低操作成本并提升美观度。

## What Changes
- 将用户登录凭证从“邮箱+密码”改为“手机号+密码”。
- 用户端移除首页中的“仅支持 V2 授权模式”提示板块（含“授权码激活引导”“V2数据迁移入口”整块）。
- root 管理端“用户管理”改为“查询区 + 新增弹窗”，新建用户仅需手机号与账号类型，默认密码展示为“手机号后6位”，并自动发放授权码（个人1个、家庭5个）。
- root 管理端“授权码管理”改为“查询区 + 新增区”，支持授权码启用与删除，列表展示手机号与授权码。
- root 管理端“账单管理”列表增加手机号与授权码展示列。
- 全局 UI（管理端+用户端）做字号、间距、层级与控件风格优化，提升整体美观性与可读性。
- 桌面端左侧导航栏宽度收窄，释放主内容区空间并保持可读性。
- UI 优化作为本次重点：建立符合大众审美的设计规范（配色、排版、间距、层级、状态反馈、响应式），统一管理端与用户端视觉语言。
- 家庭管理规则调整为“全员可管理、无管理员角色”，但必须至少保留1名成员不可删空。
- 用户端“我的信息”改为只读，仅展示账号状态、手机号绑定关系与基础信息，不提供修改动作。
- **BREAKING**：用户登录接口与前端登录入参从邮箱切换到手机号；旧邮箱登录流程不再作为默认入口。

## Impact
- Affected specs: V2认证与登录、root管理后台、授权码管理、账单管理、家庭管理、用户中心、前端设计系统
- Affected code: `backend/app/schemas.py`、`backend/app/models/models.py`、`backend/app/api/auth.py`、`backend/app/api/admin.py`、`backend/app/api/families.py`、`frontend/index.html`、`frontend/README.md`、`docs/v2_guide.md`

## ADDED Requirements
### Requirement: 手机号登录
系统 SHALL 使用手机号作为普通用户登录账号标识，并保持原密码校验机制。

#### Scenario: 登录成功
- **WHEN** 用户输入已注册手机号与正确密码
- **THEN** 返回访问令牌并进入对应角色页面

#### Scenario: 登录失败
- **WHEN** 手机号不存在或密码错误
- **THEN** 返回统一登录失败提示，不暴露账号存在性

### Requirement: 用户端首页提示板块移除
系统 SHALL 移除用户端首页“仅支持 V2 授权模式”整块提示区域，不在首页展示该信息卡片。

#### Scenario: 用户进入首页
- **WHEN** 用户登录后进入用户端首页
- **THEN** 页面不再显示“仅支持 V2 授权模式”“授权码激活引导”“V2数据迁移入口”板块

### Requirement: root用户管理弹窗化
系统 SHALL 在 root 用户管理页面提供查询与新增弹窗两块区域。

#### Scenario: root 新建个人用户
- **WHEN** root 在弹窗输入手机号并选择个人账号类型
- **THEN** 创建用户成功，默认密码规则明确展示，并自动生成1个授权码

#### Scenario: root 新建家庭用户
- **WHEN** root 在弹窗输入手机号并选择家庭账号类型
- **THEN** 创建用户成功并自动生成5个授权码

### Requirement: root授权码管理重构
系统 SHALL 提供授权码查询与新增区，并支持对授权码执行启用和删除。

#### Scenario: 查询授权码
- **WHEN** root 输入手机号或授权码关键词进行查询
- **THEN** 列表返回手机号、授权码、状态、创建时间

#### Scenario: 启用与删除
- **WHEN** root 对目标授权码执行启用或删除
- **THEN** 状态或数据即时更新并给出反馈

### Requirement: 家庭成员全员管理
系统 SHALL 允许家庭内任意成员进行成员管理，不区分管理员角色。

#### Scenario: 成员删除保护
- **WHEN** 用户尝试删除家庭最后1名成员
- **THEN** 系统拒绝操作并提示“至少保留1名成员”

### Requirement: 用户信息只读
系统 SHALL 将用户端个人信息页限制为只读展示。

#### Scenario: 查看绑定信息
- **WHEN** 用户进入个人信息页
- **THEN** 可查看手机号、账号状态、授权关系等信息且无编辑按钮

### Requirement: 左侧导航宽度优化
系统 SHALL 将桌面端左侧导航栏调整为更窄宽度，确保导航可用且主内容区更宽。

#### Scenario: 桌面端显示
- **WHEN** 用户在桌面端访问管理端或用户端页面
- **THEN** 左侧导航栏较当前更窄，主内容区可见宽度提升，导航文案不截断

### Requirement: 大众审美UI设计规范
系统 SHALL 在管理端与用户端应用统一且更符合大众审美的视觉规范，覆盖配色、分布、字体、布局与细节反馈。

#### Scenario: 配色与层级
- **WHEN** 用户浏览任意页面
- **THEN** 主次色对比清晰、信息层级明确、警告/成功/错误状态色语义一致且不过度刺眼

#### Scenario: 字体与可读性
- **WHEN** 用户阅读表单、列表、卡片、表格内容
- **THEN** 字号体系统一（标题/正文/辅助文案分级明确），行高与字重平衡，避免“整体偏大”问题

#### Scenario: 布局与细节
- **WHEN** 用户进行新增、查询、筛选、删除等高频操作
- **THEN** 模块分布清晰、留白合理、控件对齐统一，弹窗与按钮反馈细节完整（hover/active/loading/disabled）

## MODIFIED Requirements
### Requirement: root账单管理展示字段
账单列表从“仅账单字段”修改为“包含手机号与授权码字段”的可追溯视图。

### Requirement: 全局UI规范
前端整体视觉从“偏大字号”修改为“更紧凑层级和更统一控件尺寸”，并统一管理端与用户端风格语言。

## REMOVED Requirements
### Requirement: 用户端邮箱登录入口
**Reason**: 产品策略改为手机号统一识别，降低客服沟通成本并匹配手机号账号体系。  
**Migration**: 旧邮箱账号迁移到手机号字段后登录；登录页不再展示邮箱输入入口。
