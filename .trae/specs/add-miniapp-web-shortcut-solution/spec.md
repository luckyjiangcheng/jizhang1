# 快捷指令+小程序+Web后端方案 Spec

## Why
当前 V2 方案只有“快捷指令 + Web后端”，缺少小程序触达与转化入口。需要在不强制登录前提下，让新用户先体验分析能力，再平滑转入真实账单与账号体系。

## What Changes
- 新增小程序端板块：支持“未登录体验版 + 已登录真实版”双态。
- 新增项目目录 `miniapp/`，与 `backend/` 平级，所有小程序代码仅放入该目录。
- 新增体验版账单分析能力：使用虚拟数据，呈现方式与 dashboard 类似并优化交互。
- 新增产品图文介绍页：说明个人版/家庭版、申请方式（企微 xxx）、授权码带来的便利性（不引导安装）。
- 新增登录后真实账单分析：按当前手机账号聚合全部账单数据。
- 新增登录后快捷指令引导说明页：说明便利性并提供可选跳转安装入口（用户自愿触发）。
- 统一小程序 UI 设计规范：页面布局、色系、字体层级、控件交互、空态/加载态/错误态。
- 不改动现有 V1 单机版能力与入口。
- 不改动现有 V2 Web 端与快捷指令现有流程，仅新增小程序板块。

## Impact
- Affected specs: V2 账单分析展示、账号体系、快捷指令使用说明、产品介绍内容体系
- Affected code: `miniapp/` 小程序页面与组件、后端聚合查询接口、登录态与游客态网关、内容配置模块
- Unaffected code: V1 单机版页面与流程、现有 V2 Web 页面主流程、既有快捷指令接口契约

## ADDED Requirements
### Requirement: 小程序双态访问（不强制登录）
系统 SHALL 提供未登录可访问的体验版视图，并允许用户在任意时刻进入登录流程。

#### Scenario: 未登录访问
- **WHEN** 用户首次打开小程序且无登录态
- **THEN** 系统展示体验版分析 + 产品介绍入口 + 登录入口，不阻断浏览

#### Scenario: 已登录访问
- **WHEN** 用户登录成功
- **THEN** 系统切换为真实账单分析视图并展示快捷指令引导说明

### Requirement: 体验版账单分析展示
系统 SHALL 在未登录态提供基于虚拟数据的分析页，并保持与 dashboard 相近的信息架构。

#### Scenario: 体验版分析
- **WHEN** 未登录用户进入分析页
- **THEN** 展示虚拟账单数据的汇总卡片、分类分布、趋势图、明细列表
- **AND** 页面交互包含筛选、时间切换、空态提示与过渡动画

### Requirement: 产品图文介绍
系统 SHALL 提供图文介绍内容，说明个人版与家庭版能力、申请账号流程与授权码价值说明。

#### Scenario: 查看产品说明
- **WHEN** 用户进入产品介绍页
- **THEN** 页面清晰说明个人版独立使用、家庭版账单合并
- **AND** 告知“申请账号请联系企微 xxx”
- **AND** 说明“授权码授权可提升使用便利性”，但不出现强安装引导文案

### Requirement: 登录后真实账单分析
系统 SHALL 在登录态读取当前手机账号下全部账单数据并进行分析展示。

#### Scenario: 登录后数据展示
- **WHEN** 登录用户进入分析页
- **THEN** 系统按当前账号聚合账单并展示真实统计结果
- **AND** 与体验版保持一致的视觉结构与交互逻辑

### Requirement: 登录后快捷指令引导说明
系统 SHALL 在登录态提供快捷指令使用说明模块，帮助用户理解授权码与快捷记账协作方式，并支持用户主动跳转安装。

#### Scenario: 查看引导说明
- **WHEN** 登录用户打开快捷指令说明模块
- **THEN** 页面展示授权码授权路径、触发方式建议、常见问题入口
- **AND** 页面提供“去安装快捷指令”跳转入口，且默认不自动跳转

### Requirement: UI 体验与视觉一致性
系统 SHALL 提供高质量 UI 体验规范并落实在小程序关键页面。

#### Scenario: 视觉与交互验收
- **WHEN** 用户在主要页面操作（分析、介绍、引导）
- **THEN** 页面符合统一色系、字体层级、间距栅格、控件反馈与动效规范
- **AND** 在加载/错误/空数据状态下保持一致可读性与可用性

### Requirement: 兼容性与增量交付
系统 SHALL 以“新增板块”方式落地小程序方案，不影响现有 V1 与 V2 的既有能力。

#### Scenario: 兼容性验收
- **WHEN** 新增小程序板块上线
- **THEN** V1 单机版功能与入口保持不变
- **AND** V2 Web 端与快捷指令现有流程保持不变

### Requirement: 小程序代码目录边界
系统 SHALL 将小程序相关代码集中在 `miniapp/` 目录，并保持其与 `backend/` 平级，避免混入现有 V2 Web 代码目录。

#### Scenario: 目录结构验收
- **WHEN** 开发新增小程序功能
- **THEN** 所有页面、样式、配置与资源文件均位于 `miniapp/` 下
- **AND** 不在 `backend/`、现有 V2 Web 静态目录中新增小程序实现代码
